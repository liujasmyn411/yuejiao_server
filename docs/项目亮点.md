# 粤教服务 AI Agent 系统 —— 5 大核心亮点

---

## 1. 统一意图路由与多层降级机制

**核心代码**: [api/chat_routes.py](../api/chat_routes.py) — `/api/chat` 统一对话入口

**架构设计**: 所有用户消息通过单一 `/api/chat` 端点进入，经过四层路由决策，最终分发到 Customer / Enterprise / Student 三个 Agent 之一。

**核心工作流**:

```
用户消息 → LLM 意图分类（优先）
        → 本地关键词匹配（LLM 不可用时兜底）
        → 角色权限校验（学生不可访问企业 Agent，员工不可访问学生 Agent）
        → Agent 二级意图分类（8~11 种细粒度意图）
        → 执行对应处理器
```

**关键技术点**:
- **LLM + 本地双轨分类**: 优先调用 LLM 进行语义意图识别（`classify_intent`），失败时自动降级到本地关键词打分算法（4 组关键词词库：客服/企业/学生/闲聊），确保离线可用
- **角色感知路由**: `_local_classify_for_role()` 根据用户角色（游客/学生/员工/管理员）使用不同关键词库，游客仅匹配客服词，杜绝越权
- **多轮会话状态优先**: 存在活跃的槽位填充状态时，优先处理当前会话，避免意图分类干扰正在进行的多轮对话
- **话题切换 LLM 复核**: 用户在槽位填充中可能想切换话题，通过 `_llm_check_topic_switch()` 调用 LLM 做第二层逃生判断

## 2. 多轮对话槽位填充状态机

**核心代码**: [utils/conversation_state.py](../utils/conversation_state.py) — `ConversationStateManager` + `SlotState`

**架构设计**: 通用的多轮数据收集框架，将"用户想插入数据但信息不完整"的场景抽象为三阶段状态机，同时内建三层防死循环逃生机制。

**核心工作流**:

```
启动槽位填充 → 定义必填字段 → 逐轮追问缺失字段
                                   ↓
              ┌─ 收集阶段 (collecting): LLM 从用户输入提取字段值
              ├─ 确认阶段 (confirming): 展示摘要，等待用户确认
              └─ 完成阶段 (done): 写入数据库，清除状态

三层逃生机制:
  ① 关键词快速检测: "查询/查看/成绩/进度" 等切换话题词 → 立即清状态
  ② LLM 意图复核: 判断新消息是"补充信息"还是"新话题"
  ③ 交互次数上限: MAX_INTERACTIONS=5 → 自动结束防止无限循环
```

**关键技术点**:
- **通用槽位定义**: `TABLE_REQUIRED_FIELDS` 字典统一管理 5 张表的必填字段及中文显示名，新增数据收集场景只需添加配置
- **三阶段流转**: `collecting → confirming → done`，确认阶段支持用户反复修改（退回收集阶段重新提取）
- **防死循环设计**: 短输入重试计数（`confirm_retries`）、话题切换关键词检测、LLM 语义复核、交互次数兜底，四重保障
- **TTL 过期清理**: 600 秒超时自动清除，防止内存泄漏
- **上下文预填**: 已登录学生的 `student_id`、员工的 `employee_id` 自动注入，减少追问轮次

## 3. 安全可控的 NL2SQL 引擎

**核心代码**: [agents/enterprise/nl2sql.py](../agents/enterprise/nl2sql.py) — `NL2SQL` 类

**架构设计**: 将自然语言转为 SQL 的完整管线，在 LLM 生成 SQL 后执行多层安全校验，支持 SELECT 和有限 UPDATE，并自动为学生查询注入数据隔离条件。

**核心工作流**:

```
自然语言查询 → LLM 生成 SQL JSON ({sql, explanation, type})
            → 安全校验层:
               ├─ 表名白名单 (10 张表)
               ├─ 危险关键字词边界匹配 (INSERT/DROP/DELETE/TRUNCATE...)
               ├─ 危险函数模式检测 (SLEEP/BENCHMARK/INTO OUTFILE...)
               └─ UPDATE 专项校验:
                  ├─ 必须包含 WHERE + LIMIT
                  ├─ 表级白名单 (4 张表)
                  └─ 列级白名单 (每表仅允许修改指定列)
            → 学生数据隔离: 自动注入 student_id = X 到 WHERE 子句
            → 执行 SQL → 格式化返回结果
```

**关键技术点**:
- **词边界精准匹配**: 单字危险关键词（如 DELETE）使用 `\b` 正则边界匹配，避免误杀正常列名（如 `delete_flag`）
- **多词模式子串匹配**: `SLEEP(` / `BENCHMARK(` / `INTO OUTFILE` 等不可能出现在正常标识符中的模式直接用子串检测
- **UPDATE 双重限制**: 必须同时包含 WHERE 和 LIMIT，防止误操作全表更新
- **学生数据自动隔离**: `_apply_student_scope()` 智能解析 SQL 结构，在 WHERE 子句中追加 `student_id = N` 条件，先清除 LLM 可能生成的占位符或硬编码值，再注入真实 ID
- **事务安全**: UPDATE 操作通过 `db.commit()` 提交，异常时 `db.rollback()` 回滚

## 4. 三 Agent 协作架构与智能路由

**核心代码**: [agents/customer_service/agent.py](../agents/customer_service/agent.py) (8 意图)、[agents/enterprise/agent.py](../agents/enterprise/agent.py) (11 意图)、[agents/student/agent.py](../agents/student/agent.py) (8 意图)

**架构设计**: 三个独立 Agent 各司其职，每个 Agent 内部有独立的意图分类、关键词快速路由、以及专业化子模块（RAG 检索引擎、NL2SQL、心理监测、语音处理等）。

**核心工作流**:

```
┌─ CustomerServiceAgent (对外客服)
│  意图: 公司信息/业务查询/政策查询/项目推荐/活动报名/FAQ/画像匹配/投诉反馈
│  特色: RAG 知识库检索、活动报名多轮引导、游客自动创建 CRM 线索
│
├─ EnterpriseAgent (企业内部助手)
│  意图: 客户录入/查询/更新/画像研判/日报/数据查询/新人指引/审批/工单更新/仪表盘
│  特色: 关键词快速路由绕过 LLM、学生操作拦截器、闲聊主动附待办提醒
│  子模块: NL2SQL 引擎、VoiceProcessor (语音→日报)、ApprovalFlow (审批)
│
└─ StudentAgent (学生全周期助手)
   意图: 请假/心理关怀/投诉反馈/学业查询/留学进度/生活支持/增值转化/数据查询
   特色: 每条消息实时心理评估、强信号投诉词过滤、相对日期自动解析
   子模块: PsychMonitor (心理监测)、ApprovalFlow (审批)、NL2SQL (仅查自己数据)
```

**关键技术点**:
- **快速路由旁路**: EnterpriseAgent 的 `_quick_route()` 对明确模式（如"查询所有客户"）直接跳过 LLM 分类，减少延迟和 token 消耗
- **学生操作拦截**: `_block_student_action()` 检测员工/管理员试图执行学生专属操作（如"我要请假"）时，礼貌引导到正确的企业管理功能
- **闲聊主动性**: EnterpriseAgent 闲聊时自动查询待处理投诉数和待审批请假数，主动提醒用户
- **跨 Agent 子模块复用**: NL2SQL 引擎同时被 EnterpriseAgent 和 StudentAgent 使用，StudentAgent 通过 `table_allowlist` 和 `student_scope` 参数限制查询范围
- **增值转化闭环**: StudentAgent 识别学生升学意向后自动创建 CRM 线索（渠道标记"学生助手-增值转化"），打通学生服务到客户转化的完整链路

## 5. AI 驱动的实时心理监测与智能报告生成

**核心代码**: [agents/student/psych_monitor.py](../agents/student/psych_monitor.py) (心理监测) + [reports/report_generator.py](../reports/report_generator.py) (报告生成)

**架构设计**: 双引擎系统 —— 心理监测引擎对每条学生消息做实时风险评估并自动预警；报告生成引擎支持 5 类报告的 AI 洞察生成，每类报告均有本地模板兜底。

### 5a. 实时心理监测

**核心工作流**:

```
学生每条消息 → 本地关键词快速检测（高危/中危词库）
            → 高危命中 → 直接返回绝望/高危评估
            → 未命中 → LLM 深度情感评估 (emotion_tag/score/risk_level)
            → 风险等级 high/medium → 触发预警:
               ├─ 写入 student_psych_alert 表
               ├─ 更新 student_psych_profile (累计风险次数)
               └─ 生成温暖关怀回复 (按风险等级定制话术)
```

**关键技术点**:
- **两级检测**: 本地关键词（29 个高危词 + 28 个中危词）做毫秒级快速筛查，LLM 做深度语义理解，兼顾速度与精度
- **全消息覆盖**: 不仅心理关怀意图触发评估，所有意图（包括闲聊、学业查询等）都会经过 `psych.evaluate()`，实现无感监测
- **风险分层回复**: 高危→极度温和+建议联系专业咨询师；中危→表达共情+缓解压力建议；低危→轻松鼓励；无风险→正常友好

### 5b. 智能报告生成

**核心工作流**:

```
前端选择报告类型 → ReportGenerator.generate()
                 → 按类型查询数据库聚合统计
                 → 构建结构化数据摘要
                 → LLM 生成专业洞察 (Markdown 格式)
                 → LLM 失败 → 本地模板自动兜底
                 → 返回 {report_type, title, data, insight}
```

**5 类报告**:
| 报告类型 | 数据来源 | AI 洞察要点 |
|---------|---------|-----------|
| 客户经营分析 (月报) | `crm_lead` 全表 | 新增趋势、特征聚类 TOP5、流失风险分层、获客/转化/挽回建议 |
| 日报汇总 | `employee_daily_report` | 核心工作进展、关键产出、风险关键词检测、明日建议 |
| 周报汇总 | `employee_daily_report` (周范围) | 按员工分组、本周亮点、阻塞事项、下周资源调配建议 |
| 心理周报 | `student_psych_alert` + `student_psych_profile` | 情绪标签聚类、细分风险（孤独感/学业焦虑/文化冲突）、周期节点、疏导方案 |
| 投诉周报 | `student_feedback_ticket` | AI 智能分类 (7 类)、同环比趋势、热点 TOP3、改进建议 |

**关键技术点**:
- **AI + 本地双轨**: 每类报告优先调用 LLM 生成深度洞察，`_is_llm_error()` 检测失败后自动切换到本地模板（`_fallback_*_insight`），确保服务永不中断
- **流失风险智能分层**: 客户分析报告根据 `update_time` 距今天数和意向评分，将风险客户分为高/中/低三层
- **周期节点感知**: 心理周报根据当前月份判断留学周期节点（考试周/暑假/节假日），提供针对性的情绪趋势分析
- **投诉 AI 分类**: 将非结构化投诉内容通过 LLM 自动归类到 7 个预设类别（签证/院校/生活/教学/费用/住宿/其他），无需人工标注
