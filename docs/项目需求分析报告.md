### 2.3 研判规则资产（已实现）

**新加坡项目画像规则**：年龄(14-19岁)、学历(初中/高中/中职)、家庭经济(中等及以上)、教育需求(升学/就业)
- 14-16岁 → 2+2新加坡定向培养本科班
- 16-19岁 → 0.5/1+2新加坡定向培养本科班
- 17-20岁职高 → 6+6/9+6大专就业班
- 19-25岁大专/本科 → 专升本/本升硕

**德国项目画像规则**：年龄(18-35岁)、学历(高中及以上)、技能(动手/逻辑思维)、语言(德语B1)、移民意向

**统一研判函数**：`utils/file_parser.py:assess_lead_intention()` — 文件解析和AI对话浮窗共用同一套规则，评分≥50分判定为意向客户并自动录入CRM。

## 三、Agent 1：客服Agent（对外）— 已实现

### 3.1 九大意图与处理流程

```
用户输入 → LLM意图分类(temperature=0.1)
    │
    ├── company_info → RAG检索企业信息库 → LLM生成回答
    ├── business_query → RAG检索项目文档 → LLM详细介绍
    ├── policy_query → RAG检索政策指南 → LLM回答(注明政策可能变化)
    ├── project_recommend → LLM提取画像 → RAG检索 → LLM推荐+理由
    ├── event_registration → 引导查看活动/调用API报名
    ├── faq → RAG FAQ精确匹配优先 → LLM兜底 → 无结果提示转人工
    ├── profile_match → LLM提取客户信息 → 生成研判报告(匹配产品+依据+评分+建议)
    ├── feedback → 槽位填充收集投诉信息 → 确认后写入student_feedback_ticket
    └── chitchat → LLM自由对话(温暖年轻化人设)，失败时本地兜底
```

### 3.2 关键能力：客户画像研判

**实现层次**：
1. **API端点**: `POST /api/customer/profile-match` — 关键字匹配引擎（支持JSON body和query参数）
2. **Agent意图**: `profile_match` — LLM提取结构化字段 → 生成完整研判报告
3. **文件解析**: `POST /api/customer/parse-file` — 上传PDF/Excel → 提取14个画像字段 → `assess_lead_intention()` 研判 → 意向客户自动录入CRM

### 5.2 核心能力：心理风险识别

**实现**：`agents/student/psych_monitor.py` + `utils/helpers.py:emotion_analyzer()`

**识别机制**：
- **高危关键词**：不想活了、自杀、自残、绝望、崩溃、撑不住了 → 情绪分≤20，risk=high
- **中危关键词**：压力很大、焦虑、失眠、孤独、想哭、迷茫 → 情绪分30-50，risk=medium/low
- **积极关键词**：开心、谢谢、好的 → 情绪分70-100，risk=none

**预警联动**：
1. 学生对话 → PsychMonitor评估 → 生成情绪标签+分值+风险等级
2. 高危/中危 → 自动写入 `student_psych_alert` 表 + 更新 `student_psych_profile` 画像
3. 所有对话（非心理意图也附带轻量评估）→ 高风险自动触发预警

### 5.3 核心能力：日期解析（三级防御）

**文件**：`utils/date_parser.py:normalize_datetime()`

支持中文相对时间表达 → 标准datetime：
- "明天"/"后天"/"大后天" → `now.date() ± N days`
- "下周一"/"本周五" → 基于当前日期计算
- "3天后"/"2周后" → timedelta计算
- "上午"/"下午"+日期 → 自动填充时段默认时间

三级防御：`approval_flow.py`（源头）→ `agent.py:_merge_collected`（槽位合并）→ `_commit_collected`（提交前兜底）。

### 5.4 核心能力：NL2SQL自查询

**文件**：`agents/enterprise/nl2sql.py`（可配置版）+ `agents/student/prompts.py:NL2SQL_STUDENT_PROMPT`

| 角色 | NL2SQL 范围 | UPDATE |

| ADMIN/EMPLOYEE | 全部表 | 白名单列 |
| STUDENT | 仅5张学生表 + `student_scope` 自动注入 `WHERE student_id={id}` | 禁止 |

### 5.5 留学进度追踪（7阶段）

```
文书准备(1) → 文书审核(2) → 院校申请(3) → 院校反馈(4) → 录取结果(5) → 签证办理(6) → 行前准备(7)
```

## 六、统一对话入口

**文件**: `api/chat_routes.py` — 替代原 Dify 编排层

### 6.1 两级 LLM + 本地关键词兜底 + 会话状态优先

```
POST /api/chat
  ├─ 步骤0：有活跃会话状态？→ 跳过意图识别，交给 continue_data_collection
  ├─ 步骤1：LLM 分类 TOP_LEVEL_INTENTS → 选 Agent（customer/enterprise/student）
  ├─ 步骤2：LLM 不可用 → 本地关键词打分兜底
  ├─ 步骤3：角色门限制（游客→仅客服，学生→客服+学生，员工→客服+企业）
  └─ Agent 内部：LLM 分类具体意图 → 路由到处理器
```

### 6.2 角色门规则

| LLM分类 | 游客 | STUDENT | EMPLOYEE/ADMIN |
|---------|------|---------|----------------|
| student | →客服 | →学生Agent | →企业Agent |
| enterprise | →客服 | →客服Agent | →企业Agent |
| customer | →客服 | →客服Agent | →客服Agent |

### 6.3 槽位填充（多轮对话）

**文件**: `utils/conversation_state.py`

```
用户表达插入意图
  → 提取已有字段 → 缺字段则追问（collecting 阶段）
  → 字段收齐 → 展示摘要让用户确认（confirming 阶段）
  → 用户说"确认" → 写入数据库
  → 用户说"取消" → 清除状态
  → 短输入/切换话题词 → 主动提供退出选项（防死循环）
```

支持的槽位填充场景：学生请假/投诉、企业客户录入/日报提交、客服投诉反馈。

## 八、认证与安全体系 — 已实现

### 8.1 JWT + bcrypt 认证流程

```
POST /api/login → bcrypt验证密码 → 签发JWT(HS256, exp=24h) → 返回token+用户信息
后续请求 → Authorization: Bearer <token> → JWT解码 → 查用户(排除软删除) → 注入依赖
```

### 8.2 安全措施

| 措施 | 实现 |
|------|------|
| 密码存储 | bcrypt哈希（passlib），永不明文存储 |
| JWT签名 | HMAC-SHA256，密钥由 `secret_key` 环境变量配置 |
| Token过期 | 默认24小时（`access_token_expire_minutes=1440`） |
| 软删除保护 | 所有查询过滤 `delete_flag=0`，已删除用户无法登录 |
| SQL注入防护 | 参数化查询（SQLAlchemy ORM） |
| NL2SQL安全 | 词边界正则校验 + 表白名单 + 禁止关键词检测 |
| CORS控制 | 可配置允许源列表 |
| 学生数据隔离 | `enforce_self_only()` 学生只能操作自己的数据 |
| 角色访问控制 | `require_student` / `require_employee_or_admin` 依赖注入 |

### 8.3 权限模型

| 操作 | 游客 | STUDENT | EMPLOYEE/ADMIN |
|------|------|---------|----------------|
| 统一聊天→客服Agent | 是 | 是 | 是 |
| 统一聊天→学生Agent | 否 | 是 | 否 |
| 统一聊天→企业Agent | 否 | 否 | 是 |

### 11.1 RAG引擎特性

- **零外部依赖**：基于中文n-gram（1/2/3字）分词 + 关键词覆盖度打分

- **性能**：全局单例模式，首次加载后复用

## 十五、给开发者的建议

### 项目启动步骤

1. `pip install -r requirements.txt` — 安装Python依赖
2. 配置 `.env` 文件（数据库连接 + LLM API Key + secret_key）
3. `python main.py` — 启动服务（自动建表+初始化示例数据+启动定时任务）
4. 访问 `http://localhost:8000` — 前端SPA界面
5. 访问 `http://localhost:8000/docs` — Swagger API文档
6. `python -m pytest tests/ -v` — 运行全部测试

### LLM配置说明

项目设计为LLM可选模式：
- **配置了API Key**：Agent通过LLM做意图分类和信息提取（高质量）
- **未配置API Key**：返回降级提示，本地关键词兜底，不影响CRUD类API的正常使用

### 开发约定

- 所有数据库访问必须通过CRUD层，API层不直接操作DB
- 所有删除操作为软删除（`delete_flag=1`）
- 需要认证的端点使用 `Depends(get_current_user)` 或对应角色依赖
- 学生查询类端点使用 `enforce_self_only(current_user, student_id)`
- 新增表需同步更新：ORM模型 → Pydantic Schema → CRUD类 → 路由 → 测试
- 新增槽位填充场景：在 `conversation_state.py` 的 `TABLE_REQUIRED_FIELDS` 中配置必填字段
- Agent中实现 `continue_data_collection()` 方法处理多轮对话
