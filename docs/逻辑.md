# 粤教服务 AI Agent 系统 — 核心逻辑

## 一、项目架构总览（通俗版）

### 1.1 整体理解：这个项目是什么

用一句话说：**这是一个带 AI 聊天能力的内部办公系统**。

把它想象成一个"智能客服 + OA 办公"的合体网站。有三类人用它：

| 谁在用 | 用来干嘛 |
|--------|---------|
| **访客/家长** | 打开网页问 AI："新加坡留学多少钱？""有什么项目适合我？" |
| **公司员工** | 登录后管理客户、写日报、批请假、查数据 |
| **在册学生** | 登录后请假、查成绩、看留学进度、找 AI 聊天 |

所有这些功能都在**同一个网站**里，只是不同角色登录后看到的菜单不同。

---

### 1.2 前后端是什么、怎么分工

把网站想象成一个餐厅：

```
┌──────────────────────────────────────────┐
│              前端 = 餐厅大厅               │
│                                          │
│  客人看到的：菜单、桌子、服务员、装修       │
│  （用户看到的：页面、按钮、表格、聊天窗）    │
│                                          │
│  用什么做的：一个 HTML + 一个 CSS + 25个JS  │
│  不需要安装任何框架，纯手写代码              │
└──────────────────┬───────────────────────┘
                   │ 喊一声"点菜"
                   │ （发 HTTP 请求，带 JWT 令牌证明身份）
                   ▼
┌──────────────────────────────────────────┐
│              后端 = 后厨                   │
│                                          │
│  后厨做的事：接单 → 做菜 → 端出去          │
│  （服务器做的事：收请求 → 处理逻辑 → 返回数据）│
│                                          │
│  用什么做的：Python + FastAPI 框架          │
│  数据存哪：SQLite 数据库文件（一个文件就够）  │
│  大脑是谁：接了个 AI 大模型来帮忙理解对话     │
└──────────────────────────────────────────┘
```

**前端**（`static/` + `templates/`）：就是浏览器里跑的那部分代码。负责**画界面、响应用户点击**，但不会直接操作数据库。需要数据了就朝后端喊一声（发 HTTP 请求）。

**后端**（`api/`、`agents/` 等）：在服务器上跑。负责**真正干活**——查数据库、调 AI 模型、判断权限、写数据。

---

### 1.3 前端到底有哪些页面

整个网站只用**一个 HTML 文件**（`templates/index.html`），切换页面不会整页刷新，而是 JS 动态替换内容区——这就是"单页应用"。URL 里带 `#` 号区分不同页面（比如 `#/leads` 是客户管理页）。

按角色分，每个人看到的菜单不同：

**所有人都能看到的：**
- 登录页 — 输入账号密码
- 仪表盘 — 首页看板，展示关键数据

**客服/管理员专属（对外服务）：**
- 活动管理 — 创建/查看讲座活动
- 项目展示 — 查看留学项目信息
- 画像匹配 — 输入客户情况，AI 推荐适合的项目
- 文件解析 — 上传简历/表格，AI 自动提取信息

**员工/管理员专属（内部管理）：**
- 客户管理 — CRM 意向客户的新增/修改/查询
- 日报管理 — 员工提交和查看工作日报
- 成绩管理 — 录入学生成绩，支持 Excel 批量导入
- 员工通讯录 — 查看所有员工信息
- 审批管理 — 班主任审批学生的请假申请
- 组织架构 — 公司部门树形结构
- 报告中心 — 查看 AI 自动生成的各类报告
- 心理预警 — 查看学生心理预警记录

**学生专属：**
- 教务提醒 — 查看考试/作业的截止日期
- 留学进度 — 跟踪留学申请的 7 个阶段
- 请假申请 — 提交请假 + 查看历史
- 投诉反馈 — 提交投诉 + 查看处理进度
- 通知中心 — 接收审批结果等系统通知
- 个人信息 — 查看自己的信息

---

### 1.4 后端的代码怎么组织的

后端代码分成 **4 层**，从外到内：

```
用户请求
   ↓
api/     ← 第一层：接客。定义"有哪些网址可以用"（约 50 个接口）
   ↓
agents/  ← 第二层：动脑。AI Agent 理解用户想干嘛，决定怎么处理
   ↓
crud/    ← 第三层：干活。对数据库增删改查
   ↓
model/   ← 第四层：定义。15 张数据表的结构定义
   ↓
数据库
```

其他辅助模块（横跨各层）：
- `utils/auth.py` — 登录验证、权限控制（谁能看什么）
- `utils/llm_client.py` — 调用 AI 大模型的统一入口
- `utils/conversation_state.py` — 记住用户上一轮说了什么（多轮对话）
- `utils/scheduler.py` — 定时任务（每天自动提醒、生成报告）
- `knowledge_base/` — 知识库（存着公司业务 FAQ，AI 回答时来这儿找参考）

---

### 1.5 核心的 3 个 AI 助手

整个系统有 3 个 AI 助手，各管一摊：

| 助手 | 代号 | 服务谁 | 能干嘛 |
|------|------|--------|--------|
| 客服助手 | `CustomerServiceAgent` | 访客/家长（不用登录） | 介绍公司、推荐项目、回答 FAQ、帮助报名活动 |
| 企业助手 | `EnterpriseAgent` | 员工/管理员（需登录） | 管理客户、写日报、查数据（NL2SQL）、审批请假 |
| 学生助手 | `StudentAgent` | 在册学生（需登录） | 请假、心理关怀、查成绩、查留学进度 |

用户发消息 → 系统先判断你是谁、你想干嘛 → 分配给对应的助手 → 助手调用 AI 干活 → 返回结果。

### 1.6 用到的技术一览

| 干什么 | 用什么 |
|--------|--------|
| 网站框架 | FastAPI（Python 写的后端框架，自带 API 文档页） |
| 数据库 | SQLite（开发时用，一个文件搞定）/ MySQL（正式上线时换） |

| 部署启动 | Uvicorn 服务器，一行命令 `python main.py` 就跑起来 |

## 二、统一对话入口路由逻辑

**文件：** `api/chat_routes.py`

### 路由决策流程

```
POST /api/chat { message, student_id?, user_id?, session_id? }
│
├─ Step 0: 检查活跃的槽位填充会话
│   ├─ 有活跃状态 → LLM 判断是"补充信息"还是"新话题"
│   │   ├─ 补充 → 交给原 Agent 的 continue_data_collection
│   │   └─ 新话题 → 清状态，继续 Step 1
│   └─ 无活跃状态 → 继续 Step 1
│
├─ Step 1: LLM 意图分类
│   TOP_LEVEL_INTENTS = {
│     "customer": "外部客户咨询...",
│     "enterprise": "企业内部办公...",
│     "student": "留学生个人服务..."
│   }
│
├─ Step 2: LLM 失败 → 本地关键词兜底
│   _local_classify_for_role(message, user_type)
│   游客只匹配 customer/chitchat，学生匹配 student/customer/chitchat
│   员工匹配 enterprise/customer/chitchat
│
├─ Step 3: 角色权限校验 _agent_allowed_for_role()
│   student agent → 仅 STUDENT
│   enterprise agent → 仅 EMPLOYEE/ADMIN
│   customer agent → 所有人（包括游客）
│   不合规的 agent_type 自动回退到合规 agent
│
└─ Step 4: 实例化 Agent → route_intent() → 返回 {intent, response, confidence}
```

### 关键词分类表

| 角色 | 可用关键词组 | 说明 |
|------|------------|------|
| 游客 | CUSTOMER_KW + CHITCHAT_KW | 不能匹配学生/企业词 |
| STUDENT | STUDENT_KW + CUSTOMER_KW + CHITCHAT_KW | |
| EMPLOYEE/ADMIN | ENTERPRISE_KW + CUSTOMER_KW + CHITCHAT_KW | |

短输入（≤4字）且无业务词 → 直接归类为闲聊。

## 三、客服 Agent 处理逻辑

**文件：** `agents/customer_service/agent.py`

### 意图分类（9 种）

```
用户输入 → classify_intent(INTENT_DESCRIPTIONS)
  │
  ├─ company_info       → RAG检索 + LLM生成 或 固定介绍文案
  ├─ business_query     → RAG检索留学项目资料 + LLM生成
  ├─ policy_query       → RAG检索签证/政策 + LLM生成（注明政策可能变化）
  ├─ project_recommend  → LLM提取用户画像 → RAG检索 → LLM推荐
  ├─ event_registration → 查询 event_lecture 表 → 格式化活动列表
  ├─ faq                → RAG精准匹配问答对 或 LLM生成
  ├─ profile_match      → LLM提取画像 → LLM研判 → 输出评估结果
  ├─ feedback           → 槽位填充 → 确认 → 写入 student_feedback_ticket
  └─ chitchat           → LLM闲聊 或 本地关键词匹配
```

### 关键处理逻辑

**活动报名（event_registration）：**
```
1. db可用？→ 调用 EventCRUD.get_all(db)
2. 过滤状态：排除 "已结束"/"已取消"
3. 格式化输出：编号、类型、名称、时间、地点、报名截止、名额
4. db不可用 → 友好提示
```

**FAQ 检索：**
```
1. RAG检索知识库
2. 如果前20字符含"FAQ" → 精确匹配问答对 (A: 行)
3. 有上下文 → LLM基于资料回答
4. 无匹配 → 引导转人工
```

**售后反馈（feedback）—— 槽位填充流程：**
```
1. 区分"查询投诉进度"和"发起新投诉"
2. LLM提取：反馈类型/涉及人员/详细描述/期望解决方案
3. 内容不充分 → 启动槽位填充，追问缺失字段
4. 内容充分 → 进入确认阶段，展示摘要
5. 用户确认 → 调用 FeedbackCRUD.create() 写入数据库
6. 用户取消/超次 → 自动清状态
```

## 四、企业 Agent 处理逻辑

**文件：** `agents/enterprise/agent.py`

### 意图分类（10 种）+ 快速路由

入口 `route_intent()` 包含三层路由：

**第一层：短输入预检**
```
≤3字且无业务关键词 → 直接走闲聊
```

**第二层：学生操作拦截**
```
检测 "请假/投诉/我的成绩/我的学业/我的心理" → 礼貌引导到企业功能
但如果含 "审批/查询/列表/统计" → 放行（企业可查询这些）
```

**第三层：关键词快速路由 `_quick_route()`**
```
审批动词 + 请假/投诉/反馈 → approval
查询动词 + 业务对象 → data_query
画像研判关键词 + 姓名/年龄/学历 → lead_profile
```
绕过 LLM 分类，避免歧义。

**第四层：LLM 意图分类 → handler**

### 核心业务逻辑

**客户画像研判（lead_profile）：**
```
1. LLM 提取结构化信息（姓名/年龄/学历/意向国家/家庭经济/语言能力/背景）
2. 调用 assess_lead_intention() 研判函数：
   ├─ 新加坡项目匹配：14-16岁→初中项目 / 17-19岁→高中项目
   │   ├─ 学历加分（初中+15/高中+20/职高+20）
   │   ├─ 家庭经济加分（富裕+10/一般+5）
   │   └─ 职高/中专/中技 → 推荐就业班
   ├─ 德国项目匹配：18-35岁→双元制
   │   ├─ 学历加分（高中及以上+20）
   │   ├─ 德语基础+15 / 英语基础+5
   │   └─ 动手/逻辑能力+10
   └─ 综合判断：年龄<14或>40 → 不匹配，评分归零
3. 符合条件 → 自动写入 crm_lead（状态"新增意向"，渠道"AI对话-画像研判"）
4. 输出完整研判报告
```

**审批操作（approval）：**
```
1. LLM 提取：审批类型/申请编号/审批决定/审批意见/学生姓名
2. 有申请编号 → 直接审批
   ├─ 校验申请存在且状态为"待审批"
   ├─ ApprovalFlow.approve() → 通过/驳回
   └─ 创建通知给对应学生
3. 有学生姓名 → 查找该学生的待审批请假
   ├─ 多条 → 列出供选择
   └─ 单条 → 直接审批
4. 无明确目标 → 列所有待审批列表
```

**仪表盘（dashboard）：**
```
DashboardCRUD.get_stats(db) → 返回6项指标：
- lead_total, lead_new_this_month
- student_total, active_events
- pending_tickets, pending_leaves
- high_risk_alerts
```

## 五、学生 Agent 处理逻辑

**文件：** `agents/student/agent.py`

### 意图分类（9 种）+ 心理评估旁路

```python
def route_intent(user_input, student_id, db):
    result = llm.classify_intent(user_input, INTENT_DESCRIPTIONS)
    intent = result["intent"]
    response = handler(user_input, entities, student_id, db)
    
    # 所有意图都做轻量心理评估（心理关怀意图除外）
    if intent != "psych_care":
        psych_eval = psych.evaluate(user_input)
        if psych.should_alert(psych_eval):  # high 或 medium
            output["psych_alert"] = psych_eval
            _record_alert(student_id, psych_eval, db)  # 写入预警表
    
    return output
```

### 核心业务逻辑

**请假申请（admin_service）—— 完整槽位填充：**
```
1. 先判断是"查询"还是"提交"
   ├─ 查询 → 有student_id → 直接查数据库返回
   │         └─ 无student_id → 启动查询会话，要用户提供ID
   └─ 提交 → 进入槽位填充
2. LLM + ApprovalFlow.extract_leave_info() 提取：
   - 请假类型（病假/事假，支持自动推断）
   - 开始时间（支持"明天""后天""下周一"等自然语言）
   - 结束时间
   - 请假原因
3. 信息齐全 → 确认阶段（展示摘要，等待确认）
4. 信息不齐 → 列出缺失项，逐项追问
5. 确认 → StudentServiceCRUD.create_leave() → 返回申请ID+班主任信息
```

**心理关怀（psych_care）：**
```
1. PsychMonitor.evaluate() → 关键词检测 + LLM深度评估
2. PsychMonitor.generate_reply() → 根据风险等级生成温暖回复
   ├─ high：极度温和，建议联系专业咨询师
   ├─ medium：表达共情，给缓解建议
   ├─ low：轻松鼓励
   └─ none：正常友好
3. should_alert → 自动记录预警 + 更新心理画像
```

**学业查询（academic_query）：**
```
1. LLM 提取过滤条件（学术类型/课程名称/时间范围）
2. AcademicCRUD.get_by_student() 查询
3. 按课程名过滤
4. 调用 AcademicCRUD.get_upcoming(days=14) 获取即将到期DDL
5. 格式化输出（状态图标 + 截止时间 + 剩余天数）
```

**留学进度（progress_track）：**
```
1. StudyAbroadCRUD.get_by_student() 查全流程
2. StudyAbroadCRUD.get_current_stage() 查当前阶段
3. 7阶段可视化：文书准备→文书审核→院校申请→院校反馈→录取结果→签证办理→行前准备
4. 显示进度条（🟢已完成 / 🔵当前 / ⚪待开始）+ 负责人信息
```

**增值转化（upgrade_intent）：**
```
1. LLM 提取学生画像（当前学历/意向国家/专业/学位/预算）
2. 查询 course_project 表获取可选项目
3. LLM 基于画像+项目库推荐匹配项目
4. 自动写入 crm_lead（渠道："学生助手-增值转化"）
```

## 六、多轮对话槽位填充机制

**文件：** `utils/conversation_state.py`

### SlotState 状态机

```
        ┌─────────────────────────────────┐
        │         collecting              │
        │  (逐项追问缺失字段)              │
        └──────────────┬──────────────────┘
                       │ is_complete()
                       ▼
        ┌─────────────────────────────────┐
        │         confirming              │
        │  (展示摘要，等待确认/取消/补充)   │
        └──────────────┬──────────────────┘
           │              │              │
        确认           取消           补充
           ▼              ▼              │
        ┌──────┐    ┌──────────┐    ────┘
        │ done │    │ cleared  │   (回collecting)
        └──────┘    └──────────┘
```

### 三层逃生机制（防死循环）

| 层级 | 机制 | 触发条件 |
|------|------|---------|
| 第一层 | 关键词检测 | 用户输入含 `SWITCH_TOPIC_KW`（查询/查看/成绩/活动/请假等） |
| 第二层 | LLM 语义判断 | `_llm_check_topic_switch()` 判断是"补充信息"还是"新话题" |
| 第三层 | 交互次数兜底 | `interaction_count > MAX_INTERACTIONS (5)` → 自动清状态 |

### 必填字段定义（TABLE_REQUIRED_FIELDS）

| 表名 | 必填字段 |
|------|---------|
| student_feedback_ticket | student_id, content |
| student_admin_service | student_id, service_type, leave_type, start_time, end_time, reason |
| crm_lead | customer_name, owner_employee_id |
| employee_daily_report | employee_id, content |

`context` 参数中的字段自动跳过（如 student_id 从请求上下文注入）。

## 七、NL2SQL 安全引擎

**文件：** `agents/enterprise/nl2sql.py`

### 多层安全校验

**SELECT 安全：**
```
1. 语句必须以 SELECT 开头
2. 黑名单词边界检测：禁止 INSERT/DELETE/DROP/ALTER/TRUNCATE/CREATE/EXEC 等
3. 黑名单函数检测：禁止 INTO OUTFILE/LOAD_FILE/SLEEP()/BENCHMARK()
4. 表白名单校验：FROM/JOIN 中的表必须在 ALLOWED_TABLES 中
   (sys_user/crm_lead/student_score/student_academic/...共11张表)
```

**UPDATE 安全（更严格）：**
```
1. 必须有 WHERE 条件（防全表更新）
2. 必须有 LIMIT 限制（防批量误更新）
3. 表级白名单：仅 crm_lead / student_feedback_ticket / student_admin_service / student_academic
4. 列级白名单：每张表只允许修改特定列
   - crm_lead: status, follow_up_history, next_follow_time, score, owner_employee_id
   - student_feedback_ticket: status, solution, handle_user_id, handle_time, is_notified
   - student_admin_service: status, reject_reason, approver_id, notify_status
   - student_academic: ddl_status, remind_enabled, remind_days_before
```

**学生数据隔离：**
```
student_scope 参数 → _apply_student_scope() 自动在 WHERE 中注入 student_id 条件
- 只对 student_score / student_admin_service / student_feedback_ticket
  / student_academic / student_study_abroad_progress 生效
- 先清理 LLM 可能生成的占位符 (student_id = ?) 和硬编码 ID
- 再追加正确的 student_id 条件
```

## 八、心理监测引擎

**文件：** `agents/student/psych_monitor.py`

### 两级评估

```
用户消息 → 本地关键词快速检测
  ├─ 命中高危词（自杀/自残/不想活/绝望...）→ risk_level=high，直接返回
  │   不走LLM，保证响应速度
  ├─ 命中中危词（失眠/孤独/焦虑/压力大/想哭...）→ risk_level=medium
  │   继续走 LLM 做精细评估
  └─ 未命中 → LLM 深度评估
       └─ LLM 不可用 → 回退到关键词结果
```

### 评估输出

```json
{
  "emotion_tag": "焦虑",
  "emotion_score": 25,
  "risk_level": "medium",
  "trigger_reason": "检测到中危关键词: 失眠"
}
```

### 回复生成（分风险等级指导）

| 风险等级 | 指导策略 |
|---------|---------|
| high | 极度温和，表达关心，建议联系专业心理咨询师或信任的老师 |
| medium | 表达理解和共情，肯定感受，给缓解压力的小建议 |
| low | 轻松温暖的语气，适当鼓励 |
| none | 正常友好地回应 |

### 预警触发条件

`should_alert(evaluation)` → `risk_level in ("high", "medium")` → 自动写入 `student_psych_alert` + 更新 `student_psych_profile`

## 九、审批流程引擎

**文件：** `agents/student/approval_flow.py`

### 请假审批闭环

```
学生提交请假 → StudentAdminService(status=待审批)
  │
  ├─ 自动预填 approver_id = 学生的 head_teacher_id
  │
  ▼
班主任查看待审批列表 → get_pending_by_teacher(teacher_id)
  │  通过 head_teacher_id 关联查询名下所有学生的待审批申请
  │
  ▼
审批操作 → approve(request_id, approver_id, approved, reject_reason)
  ├─ 通过 → status="已通过", notify_status=1
  └─ 驳回 → status="已驳回", reject_reason=..., notify_status=1
  │
  ▼
创建通知 → NotificationCRUD.create()
  ├─ 通过: leave_approved → "您的请假申请已审批通过"
  └─ 驳回: leave_rejected → "已被驳回。原因：..."
```

### 自然语言日期解析

`extract_leave_info()` 调用 `normalize_datetime()` 支持：
- 相对日期：今天/明天/后天/大后天/昨天
- 星期：本周一/下周三/下周一
- 偏移：3天后/2周后
- 月份：下月5号/本月10号
- 时间段：上午/中午/下午/晚上
- 标准格式：2026-05-20 14:00 / 2026-05-20T14:00:00

## 十、RAG 检索引擎

**文件：** `knowledge_base/vectorizer.py`

### 轻量检索（零外部依赖）

```
1. 文档加载 → 按章节切分 → 建索引
2. FAQ 问答对加载 → 预计算 token 集 + 关键词倒排索引
3. 检索流程：
   ├─ 停用词过滤（保留教育/商业领域高频词）
   ├─ 同义词扩展（"咋报名"→"报名流程"、"退钱"→"退费"等）
   ├─ FAQ 精确匹配：关键词命中 + token 覆盖度排序
   └─ 文档模糊匹配：token 覆盖度排序
4. 返回 top-K 相关 chunk
```

### 同义词映射（部分）

| 用户口语 | 知识库书面语 |
|---------|------------|
| 咋报名/怎么报名 | 报名流程 |
| 退钱/能退/退款 | 退费 |
| 办签证/签证咋办 | 签证流程/签证办理 |
| 在哪 | 地址/位置 |
| 多少钱/要多少/贵不贵 | 学费/费用/价格 |
| 回国认可/承认吗 | 学历认证/教育部认证 |

## 十一、客户画像研判引擎

**文件：** `utils/file_parser.py` 中的 `assess_lead_intention()`

### 研判规则（双项目匹配）

**新加坡国际本硕升学计划匹配：**
```
年龄 14-16 → 初中毕业生项目 (2+2新加坡定向培养本科班) → +20分
年龄 17-19 → 高中/中职毕业生项目 (0.5/1+2国际本科班) → +25分
  ├─ 职高/中专/中技 → 推荐就业班 (6+6酒店/9+6航空) → +30分
学历匹配：初中+15, 高中/职高/中专+20, 大专+10, 本科+5
家庭经济：富裕/良好+10, 一般+5
```

**中德精英人才共建计划匹配：**
```
年龄 18-35 → +15分
学历高中/大专/本科/硕士 → +20分, 初中→0分（不符合）
德语基础 → +15分, 英语基础 → +5分
动手/逻辑/技术能力 → +10分
```

**综合判断：** 年龄<14 或 >40 → 不匹配，评分归零。有留学/出国/海外意愿 → +5分。

### 自动录入

研判结果为"符合意向"时，自动写入 `crm_lead` 表（状态"新增意向"，渠道"AI对话-画像研判"）。
