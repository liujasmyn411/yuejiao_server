# 粤教服务 AI Agent — 项目开发文档

## 1. 项目概述

**项目名称**: 粤教服务 AI Agent
**功能定位**: 面向国际教育服务行业的智能助手平台，提供客服接待、企业办公、学生服务三大场景的 AI Agent 能力  
**技术选型**: Python 3.10+ / FastAPI / SQLAlchemy / Pydantic v2 / 原生 JS 前端 SPA

### 1.1 三大业务场景

| 场景 | 服务对象 | 核心能力 |
|---|---|---|
| 客服Agent | 外部潜在客户 | 问答、项目推荐、画像研判、活动报名、FAQ、投诉反馈 |
| 企业智能助手 | 内部员工 | CRM管理、日报、NL2SQL查询、新人指引、仪表盘、审批、画像研判 |
| 学生智能助手 | 在册学生 | 请假、心理关怀、教务查询、留学进度追踪、海外生活支持、增值转化、NL2SQL自查询 |

```
│  static/ + templates/  前端（SPA单页应用）        │
└────────────────────────────────────────────────┘
```

### 2.2 请求处理流程

```
用户请求 → API路由 → 参数校验(Pydantic)
                  → 认证校验(JWT Bearer Token / 可选登录)
                  → CRUD层(DB操作)
                  → 返回JSON

Agent请求 → /api/chat统一入口
         → 步骤0：有活跃会话状态？→ 跳过意图识别，继续槽位填充
         → 步骤1：LLM两级意图分类（顶级→Agent内部）
         → 步骤2：LLM不可用 → 本地关键词打分兜底
         → 步骤3：角色门限制（游客→仅客服，学生→客服+学生，员工→客服+企业）
         → Agent内部：LLM分类具体意图 → RAG检索/LLM生成/槽位填充 → 返回结果
```

### 5.2 数据库连接

`Settings.database_url` 属性自动根据 `db_type` 生成连接字符串：
- MySQL: `mysql+pymysql://user:pass@host:port/db?charset=utf8mb4`
- SQLite: `sqlite:///./yuejiao.db`

连接池配置：pool_size=10, max_overflow=20, pool_recycle=3600, pool_pre_ping=True。

## 6. 认证与权限体系

### 6.1 JWT + bcrypt 认证流程

**文件**: [utils/auth.py](utils/auth.py)

```
登录请求 → 查用户 → bcrypt验证密码 → 签发JWT(HS256) → 返回token
API请求 → 提取Authorization: Bearer <token> → JWT解码 → 查用户 → 注入依赖
```

### 6.2 核心函数

| 函数 | 说明 |
|---|---|
| `hash_password(plain)` | bcrypt哈希密码 |
| `verify_password(plain, hashed)` | bcrypt校验密码 |
| `create_access_token(data, expires_delta)` | 签发JWT（HS256，含exp） |
| `decode_access_token(token)` | 解码JWT，失败返回None |
| `get_current_user(credentials, db)` | FastAPI依赖：从Bearer头解析当前用户，401拦截 |
| `get_optional_user(credentials, db)` | 可选登录依赖：有token则解析，无则返回None（用于统一聊天入口） |
| `require_student(current_user)` | 角色依赖：仅STUDENT可访问 |
| `require_employee_or_admin(current_user)` | 角色依赖：仅EMPLOYEE/ADMIN可访问 |
| `enforce_self_only(current_user, target_user_id)` | 学生只能操作自己的数据，否则403 |

### 6.3 权限模型

| 操作 | 游客 | STUDENT | EMPLOYEE/ADMIN |
|------|------|---------|----------------|
| 统一聊天→客服Agent | 是 | 是 | 是 |
| 统一聊天→学生Agent | 否 | 是 | 否 |
| 统一聊天→企业Agent | 否 | 否 | 是 |
| 查自己的信息/请假/反馈/教务/进度 | 否 | 是 | 是 |
| 查他人的信息/请假/反馈/教务/进度 | 否 | 否 | 是 |
| 提交请假/投诉 | 否 | 是 | 否 |
| 处理投诉工单 | 否 | 否 | 是 |
| 查心理预警 | 否 | 否 | 是 |
| NL2SQL | 否 | 是(仅自己) | 是(全部) |
| CRM/日报/审批 | 否 | 否 | 是 |

### 6.4 认证保护模式

- 缺失 `Authorization` 头 → 401 "未提供认证令牌"
- JWT无效/过期 → 401 "无效的认证令牌"
- 用户已软删除 → 401 "用户不存在或已注销"
- 学生访问他人数据 → 403 "仅可查看/操作自己的数据"

## 11. 槽位填充框架（多轮对话）

### 11.1 架构

**文件**: [utils/conversation_state.py](utils/conversation_state.py)

当用户意图为"向表中插入数据"时（请假/投诉/录入客户/日报），AI持续追问直到所有必填字段收集完毕：

```
用户表达插入意图
  → 提取已有字段 → 缺字段则追问（collecting 阶段）
  → 字段收齐 → 展示摘要让用户确认（confirming 阶段）
  → 用户说"确认" → 写入数据库
  → 用户说"取消" → 清除状态
  → 短输入/切换话题词 → 主动提供退出选项
```

### 11.2 核心组件

| 组件 | 说明 |
|---|---|
| `SlotState` | 单次数据收集会话的槽位状态：intent/table_name/required_fields/collected/missing/phase |
| `ConversationStateManager` | 基于用户ID管理多轮对话状态（TTL=600秒） |
| `TABLE_REQUIRED_FIELDS` | 各表必填字段定义（feedback/leave/crm_lead/daily_report） |
| `INTENT_TO_TABLE` | 意图→表名映射 |

## 12. 知识库系统

### 12.1 架构

```
knowledge_base/
├── loader.py       # 文档加载：load_documents(), load_qa_pairs()
├── splitter.py     # 文本切片：split_text(chunk_size=400, overlap=40)
├── vectorizer.py   # RAG引擎：关键词n-gram检索 + 覆盖度打分
├── data/           # 原始知识数据（10个文件）
│   ├── 公司业务/    # 新加坡国际本硕升学计划、中德精英人才共建计划
│   ├── 公司信息/    # 企业信息、公司新人指南、海外生活
│   ├── 留学政策/    # 新加坡留学政策指南、德国留学政策指南
│   └── 用户研判规则/ # 用户画像研判规则、用户信息数据示例
└── documents/      # 待处理语料目录
```

### 12.2 RAGEngine 检索流程

1. **加载**: 遍历 `data/` 下所有 `*问答对*.txt` 文件解析Q&A对 + 加载普通文档并切片
2. **分词**: 中文 n-gram（1/2/3字）无依赖分词
3. **检索优先级**: 问答对精确匹配（score=100） > 文档片段关键词覆盖度打分
4. **返回**: 最多5条最相关结果，拼接为上下文（≤2000字符）
5. **全局单例**: `get_rag_engine()` 全局复用，首次调用时加载

## 22. 开发规范

### 22.1 添加新接口

1. 在 `schemas/schemas.py` 定义请求/响应模型（继承 `BaseModel`）
2. 在对应 `crud/xxx_crud.py` 添加数据访问方法（如果有新DB操作）
3. 在对应 `api/xxx_routes.py` 添加路由处理函数
4. 如需新的路由文件，在 `api/__init__.py` 中 `include_router`
5. 在对应 `tests/test_xxx.py` 添加测试用例

### 22.2 添加新Agent意图

1. 在 `agents/xxx/prompts.py` 的 `INTENT_DESCRIPTIONS` 中添加新意图描述
2. 在 `agents/xxx/agent.py` 的 `handlers` 字典中注册新的 handler
3. 实现 `_handle_xxx` 方法
4. 如需槽位填充，在 `conversation_state.py` 的 `TABLE_REQUIRED_FIELDS` 中配置必填字段

### 22.3 新增数据库表

1. 在 `model/model.py` 添加 ORM 类（继承 `Base`）
2. 在 `schemas/schemas.py` 添加对应的 Pydantic Schema
3. 在对应 `crud/xxx_crud.py` 添加 CRUD 类
4. 在 `crud/__init__.py` 中导出新类

### 22.4 数据库操作规范

- **API层不直接操作DB**：所有数据库访问必须通过 CRUD 层
- **软删除**：所有删除操作使用 `delete_flag=1`，不做物理删除
- **参数校验**：Pydantic 模型负责输入校验，CRUD 层不做重复校验
- **认证保护**：需要认证的端点使用 `Depends(get_current_user)` 或对应的角色依赖
- **学生数据隔离**：学生查询类端点使用 `enforce_self_only(current_user, student_id)`
