# 粤教服务 AI Agent — 项目开发文档

## 1. 项目概述

**项目名称**: 粤教服务 AI Agent API  
**功能定位**: 面向国际教育服务行业的智能助手平台，提供客服接待、企业办公、学生服务三大场景的 AI Agent 能力  
**技术选型**: Python 3.10+ / FastAPI / SQLAlchemy / Pydantic v2

### 1.1 三大业务场景

| 场景 | 服务对象 | 核心能力 |
|---|---|---|
| 客服Agent | 外部潜在客户 | 问答、项目推荐、画像研判、活动报名 |
| 企业智能助手 | 内部员工 | CRM管理、日报、NL2SQL查询、新人指引 |
| 学生智能助手 | 在册学生 | 请假、心理关怀、教务查询、留学进度追踪 |

## 2. 项目架构

### 2.1 分层架构

```
┌─────────────────────────────────────────┐
│  api/  路由层（HTTP 请求/响应）          │
│  system / customer / enterprise /       │
│  student / report                       │
├─────────────────────────────────────────┤
│  agents/  智能体层（意图识别+业务逻辑）   │
│  CustomerServiceAgent                   │
│  EnterpriseAgent / StudentAgent          │
├─────────────────────────────────────────┤
│  crud/  数据访问层（封装DB操作）          │
│  customer / enterprise / student        │
├─────────────────────────────────────────┤
│  model/  数据模型层（ORM）               │
│  schemas/  数据校验层（Pydantic）        │
├─────────────────────────────────────────┤
│  knowledge_base/  知识库（RAG检索）      │
│  reports/  智能报告引擎                  │
│  utils/  工具（LLM客户端、语音等）        │
└─────────────────────────────────────────┘
```

### 2.2 请求处理流程

```
用户请求 → API路由 → 参数校验(Pydantic) → CRUD层(DB操作) → 返回JSON
                  → Agent路由 → 意图识别 → RAG检索/LLM生成 → 返回结果
```

## 9. Agent 智能体层

### 9.1 通用架构

每个 Agent 遵循相同的处理模式：

```
用户输入 → LLM意图分类 → 路由到Handler → (RAG检索 + LLM生成) → 返回结果
```

核心依赖：
- `LLMClient` — OpenAI 兼容接口统一调用 ([utils/llm_client.py](utils/llm_client.py))
- `RAGEngine` — 本地知识库检索 ([knowledge_base/vectorizer.py](knowledge_base/vectorizer.py))

### 9.2 客服Agent — `CustomerServiceAgent`

**文件**: [agents/customer_service/agent.py](agents/customer_service/agent.py)  
**支持意图**: 8种（company_info, business_query, policy_query, project_recommend, event_registration, faq, profile_match, chitchat）

**处理逻辑**：
- **公司信息/业务/政策查询**: RAG检索知识库 → LLM基于上下文回答
- **项目推荐**: 先提取用户画像（年龄/学历/意向国家/预算）→ RAG检索 → LLM推荐
- **画像研判**: 提取客户信息 → LLM生成匹配产品+依据+评分+建议
- **FAQ**: RAG精确问答对匹配优先；无匹配则LLM生成；都无结果提示转人工
- **闲聊**: LLM自由对话

### 9.3 企业助手Agent — `EnterpriseAgent`

**文件**: [agents/enterprise/agent.py](agents/enterprise/agent.py)  
**支持意图**: 10种（lead_create/query/update, daily_report, report_query, data_query, company_guide, approval, dashboard, chitchat）

**处理逻辑**：
- **CRM操作**: LLM提取客户信息（姓名/年龄/学历/意向等）→ 引导确认 → 提示调用对应API
- **数据查询**: 通过 `NL2SQL` 将自然语言转SQL → 执行查询 → 格式化展示
- **日报**: 通过 `VoiceProcessor` 将口述文本结构化 → 允许编辑提交
- **新人指引**: RAG检索知识库中的公司制度文档
- **审批**: 提取审批信息 → 引导调用API

### 9.4 学生助手Agent — `StudentAgent`

**文件**: [agents/student/agent.py](agents/student/agent.py)  
**支持意图**: 7种（admin_service, psych_care, feedback, academic_query, progress_track, life_support, upgrade_intent）

**处理逻辑**：
- **心理关怀**: `PsychMonitor` 评估情绪 → 温暖回复 + 高危自动触发预警写库
- **请假/反馈**: 提取信息 → 引导确认 → 提示调用API
- **教务查询**: 从DB查询考试/论文DDL → 标记到期时间
- **留学进度**: 从DB查询7阶段进度 → 展示当前阶段+负责人
- **海外生活**: RAG检索海外生活问答库 → LLM回答
- **增值转化**: 识别在读学生的升学意向 → 推荐升级项目 → 自动创建CRM线索
- **所有对话**: 附带轻量心理评估，高风险自动预警

## 10. 知识库系统

### 10.1 架构

```
knowledge_base/
├── loader.py       # 文档加载：load_documents(), load_qa_pairs()
├── splitter.py     # 文本切片：split_text(chunk_size=400, overlap=40)
├── vectorizer.py   # RAG引擎：关键词n-gram检索 + 评分打分
├── data/           # 原始知识数据（问答对txt文件）
└── documents/      # 待处理语料目录
```

### 10.2 RAGEngine 检索流程

1. **加载**: 遍历 `data/` 下所有 `*问答对*.txt` 文件解析Q&A对 + 加载普通文档切片
2. **分词**: 中文 n-gram（1/2/3字）无依赖分词
3. **检索**: 问答对精确匹配（score=100）优先 → 文档片段关键词覆盖度打分
4. **返回**: 最多5条最相关结果，拼接为上下文（≤2000字符）

### 10.3 当前知识库数据

| 类别 | 内容 |
|---|---|
| 公司业务 | 新加坡国际本硕升学计划、中德精英人才共建计划 问答对 |
| 公司信息 | 企业信息、公司新人指南、海外生活 问答对 |
| 留学政策 | 新加坡留学政策指南、德国留学政策指南 问答对 |

## 12. LLM 客户端

**文件**: [utils/llm_client.py](utils/llm_client.py)

`LLMClient` 通过 OpenAI 兼容接口调用大模型，支持 GPT/DeepSeek/通义千问等。

**核心方法**：
- `chat(system_prompt, user_message)` — 单轮对话
- `classify_intent(user_input, intents)` — 意图分类（temperature=0.1）
- `extract_info(user_input, fields)` — 结构化信息提取
- `generate_report(report_type, data)` — 数据驱动报告生成

**特性**：
- 未配置API Key时返回降级提示（不抛异常）
- 30秒超时保护
- 全局单例模式

1. 在 `schemas/schemas.py` 定义请求/响应模型（继承 `BaseSchema`）
2. 在对应 `crud/xxx_crud.py` 添加数据访问方法（如果有新DB操作）
3. 在对应 `api/xxx_routes.py` 添加路由处理函数
4. 如需新的路由文件，在 `api/__init__.py` 中 `include_router`

### 14.2 添加新Agent意图

1. 在 `agents/xxx/prompts.py` 的 `INTENT_DESCRIPTIONS` 中添加新意图描述
2. 在 `agents/xxx/agent.py` 的 `handlers` 字典中注册新的 handler
3. 实现 `_handle_xxx` 方法

### 14.3 新增数据库表

1. 在 `model/model.py` 添加 ORM 类（继承 `Base`）
2. 在 `schemas/schemas.py` 添加对应的 Pydantic Schema
3. 在对应 `crud/xxx_crud.py` 添加 CRUD 类
4. 在 `crud/__init__.py` 中导出新类

### 14.4 数据库操作规范

- **API层不直接操作DB**：所有数据库访问必须通过 CRUD 层
- **软删除**：所有删除操作使用 `delete_flag=1`，不做物理删除
- **参数校验**：Pydantic 模型负责输入校验，CRUD 层不做重复校验
